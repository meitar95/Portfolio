title: Designing for 10 alerts and 10,000
tagline: A dark-web threat intel dashboard that had to feel calm with 10 alerts and still hold up with 10,000.
card: Dashboards and an asset inventory for a dark-web threat intelligence platform, built on one widget system that works for teams of any size.
order: 3
cover: /images/cybersixgill
coverAlt: "Cybersixgill threat-hunting dashboard with alert counts, top threat actors and trending CVEs"
visual: cybersixgill-screens

why: >-
  Cybersixgill pulled threat intel from the deep and dark web: forums, markets, paste
  sites, chat apps. Analysts opened it to answer one question, what's threatening my
  company right now? The same screens had to work for a five-person security team and
  for an enterprise with thousands of alerts and over eleven thousand assets.
role: Product Designer via UI Human Factors
team: UI Human Factors design team, Cybersixgill product and engineering
timeline: ~1 year · 2022
platform: Threat intelligence, B2B web

outcomes:
  - value: "10 → 10K"
    label: every widget designed to hold numbers from ten to ten thousand
  - value: "1 grid"
    label: for every dashboard widget, so new ones just drop in
  - value: "11K+"
    label: assets the inventory was designed to handle, sorted by risk

solution:
  summary: >-
    One strict grid for every widget, each widget drawn at three data volumes, and an
    asset inventory where teams decide once what to watch.
  points:
    - title: One widget grid
      text: 3 columns by 3 rows make a small widget, with 16px between them, lined up with the search bar.
    - title: Built for volume
      text: I drew each widget with regular, 100+ and 1k+ data, so a big number never breaks the layout.
    - title: Riskiest first
      text: Domains, IPs, executives and more in one table, with new and risky items on top.
    - title: Set it once
      text: Teams choose what to watch and what to skip, instead of cleaning the list by hand every week.

learned: >-
  Security dashboards get judged on their worst day, when the numbers spike. So I
  started designing every widget for the biggest customer first, then checked it still
  felt calm for the smallest one. That habit stuck with me.

## The problem

A threat feed only helps if it fits on the screen. A widget could show 10 for one customer and 10,000 for the next, and the layout had to handle both.

<NumberScale />

## The evidence

### One grid for every widget

Instead of designing each dashboard from scratch, we set one rule every widget follows. That way a new widget just drops into the grid.

<WidgetGrid />

### An inventory that cleans itself

Attack surface monitoring added thousands of assets per customer. We designed the flow so the list stays useful without anyone pruning it by hand.
