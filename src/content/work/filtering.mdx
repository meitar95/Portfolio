  times a day. They weren't going to tell us. They would have quietly stopped using the
  product, and that could have cost us more than one client.
role: Sole Product Designer

  - value: "4 → 1"

  - value: "3"
    label: at-risk clients whose struggle I caught in recordings
  - value: "~10"
    label: users validated the flow before engineering started

solution:
  summary: >-
    Filtering is basic data behavior. Users shouldn't have to learn a new way to do it.
    So I gave them the familiar model they expect, in one system with one vocabulary,
    across every module.
  points:
    - title: Ask AI
      text: Product asked for an AI helper; I decided where it lives and how it behaves. Instead of a side chat, it sits in the filter bar, so a plain-language request changes the table itself.
    - title: Simple / Advanced
      text: The essentials up front; the classic field → operator → value builder one click away.
    - title: Grouped filters
      text: 28 flat fields organized into families, showing only what applies to each customer.
    - title: Save View
      text: Save a filter set and come back to it, with no repeated setup for daily investigations.

learned: >-
  High usage can be a symptom, not a success. Our most-used feature was where users
  struggled most, and they blamed themselves instead of telling us. Now we watch what
  people do before trusting what a dashboard says.
